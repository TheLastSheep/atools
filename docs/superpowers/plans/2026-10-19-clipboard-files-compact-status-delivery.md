## 用户可见结果

搜索底栏按实际容器宽度调整，而不是只看整个浏览器宽度。800px 保留全部提示，480px 合并上下移动提示，320px 的额外健壮性检查保留完整序号和 Enter/Tab/Esc。34px 宿主高度保持不变；真实 App 的 480px 深色布局不再截断“执行”等标签，状态和提示不重叠。

长名称、目标和反馈采用明确省略号，保留完整 DOM、title 和原 live status；这不是承诺在单行内常驻显示任意长反馈。Tab 目标设置入口仍可点击。使用 CSS 容器查询，没有增加全局监听或测量循环。

普通桌面插件注入中的 getCopyedFiles/getCopiedFiles 现在通过已有授权剪贴板会话同步返回新数组，包含真实 name/path/isFile/isDirectory；保留 isDiractory 作为既有错误拼写的同值别名。原版同步调用此前拿到 Promise，可能跳过数组长度及文件恢复分支。独立 QuickJS/Node harness 的旧实现不在本次修复范围。

## 底层契约与预算

同一 read endpoint 精确接受 `{}` 读取文本，或 `{format:"files"}` 读取文件元数据；write 仍只接受 `{text:string}`。未知字段、格式或方向在创建调用票据和 TaskRun 前拒绝。权限缺失同步抛错，只请求 read 一次，不排队或重放；关闭、撤销、文档失效及会话轮转继续受原有权限与生命周期约束。

macOS 使用 AppKit NSPasteboardItem 的 public.file-url、NSURL 和真实文件系统元数据，保留路径空格、Unicode、换行，不拆行或 trim，不读取文件内容，不运行外部命令。非 macOS 明确不支持。尚未支持旧 NSFilenamesPboardType、文件 promise 转换；超过 128 个混合 pasteboard items 也会保守拒绝。

限额为 128 项、单路径 8 KiB、累计路径 64 KiB、完整 HTTP 响应 envelope 256 KiB。超限或单项元数据失败时整体失败，不返回部分成功数组；错误不含文件路径。返回数据只保留在临时调用响应中，TaskRun 不保存路径、文件内容或端点凭据。数量和字节预算不代表元数据或 pasteboard 读取具有硬耗时上限，慢文件系统的同步阻塞仍是后续性能事项。
