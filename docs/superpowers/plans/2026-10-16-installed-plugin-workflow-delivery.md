## 工程边界

`PluginInventoryController` 负责事务，`installedPluginBoundary` 校验 IPC 记录；畸形写入返回按“原生已提交，等待回读”处理，畸形清单不替换最后有效清单。空字符串功能 code 可展示，不能打开。单调 `commitRevision` 只在原生写入成功后递增，避免旧操作在新事务中清空筛选或抢回详情。

`list_plugins` 通过原生 DTO 添加 `source_kind`，在后台任务中规范化实际插件路径和两个可信根目录；根路径每次读取仅规范化一次。目录组件包含关系区分内置、管理目录内导入和外部目录，软链接按真实目标判断。UI 不凭插件名、目录名或路径子串授权。旧记录显示“待确认”；只有已确认内置来源能直接重新启用，导入/外部/旧记录走权限确认，只有管理目录内导入允许更新/卸载。

打开功能继续经过现有 App 激活握手、明确的 owner/code 和原生执行管线；目录定位继续经 `call_agent_tool` 人类任务入口。没有新增执行旁路。新语义模块与组件均少于 500 行，旧设置页移除原库存职责。
