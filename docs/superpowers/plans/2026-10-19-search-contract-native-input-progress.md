# ATools 搜索兼容与原生输入进展（batch35）

本轮完成搜索规则兼容、文件误候选修复和写入前预算校验。目标继续保持进行中：尚未证明大部分 ZTools 插件可以直接使用，也未完成与 ZTools/uTools 的同机交互和完整内存对比。

## 本轮交付

- 普通搜索与固定文本匹配分别遵循已核对的 ZTools 调用契约：普通搜索去除正则标志并处理 over.exclude；固定文本保留有效标志、不使用 over.exclude。typed 正则必须使用斜杠声明，普通文本不再从路径或扩展名推断成文件、图片输入。通用底层正则接口未改为这一专用契约。
- 匹配程序在索引建立时编译，共享一个显式查询缓存。并发忙、输入超额、工作额度和程序额度失败均返回明确错误，整次拒绝，不返回部分候选。普通与固定文本均限制为 256 KiB UTF-8 输入；正则字节×规则工作额度为 32 MiB。
- 插件安装、静态重建、启用和动态规则修改在事务提交前校验程序预算。过大合法量词不能通过一次成功写入破坏整个搜索目录；失败保留旧声明、插件元数据和已缓存目录，禁用、删除仍可用于恢复。
- 修复文件筛选中把 RegexSet 的总规则数误认为命中数的问题。回归覆盖 8→9 条规则的算法切换、部分命中、零命中、多个文件的交集以及 1200 条异质规则的精确结果。
- 原生输入观测增加有界的组合输入、输入类型和目标事件计数。测试控制器只允许两项编辑器的六个固定动作，逐字符检查临时应用 PID 和前台状态，并在已授权的 ABC 临时切换后恢复原输入源。不采集按键值或任意用户输入。

官方契约独立检查为 79 组、158 项；保留原始声明、失败探针及已知 JS/Rust 语义差异。这不是完整 ECMAScript 正则实现，也不等于插件整体可用性。

## 原生编辑器验收

本轮共 5 次原生尝试，整体通过 0 次，所有失败均保留。

- 纯文本 v1 未发送固定输入：桌面控制调用返回时临时窗口已经结束。
- 纯文本 v2 已通过授权控制器写入精确 alpha 文本。实际记录 74 次可信 keydown、71 次 beforeinput、71 次 input；mousedown 与 click 各 1，pointerdown 为 0，iframe 的 document.hasFocus 为 false。组合输入已结束，ABC 已恢复为原拼音输入源。原验收条件保持，因此仍在 alpha 失败，未进入 beta。事件数不等于正文长度。
- JSON v1 缺少原生结果报告，原因未确认；窗口检查也超时，未发送固定输入。
- JSON v2、v3 在 valid 阶段失败。三次固定输入调用都被“目标仍存活、标识正确且在前台”的组合保护拒绝，未记录输入分发成功，页面可信输入计数均为 0。不能据此断言 JSON 编辑器拒绝了已送达的键盘输入。格式化、错误诊断与恢复没有实际通过证据。
- 后置 Swift 只读检查发生在窗口退出后，不能解释此前保护拒绝的具体原因。

四次有原生报告的尝试有 TaskRun 终态和运行时排空记录；缺报告的 JSON v1 对这些状态保持未知。五次外层进程与临时目录清理均有记录，原包和选定源码字节未改。JSON 的部分资源采样遗漏独立 WebKit/XPC 进程，不能作为完整应用 RSS 通过证明。未验证真人硬件输入，也未操作系统剪贴板。
